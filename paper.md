# Summary

This submission is a set of open learning modules that teach the main methods of computational intelligence through medical and biomedical problems. It contains nine Jupyter notebooks and 80 standalone Python scripts. They cover machine-learning fundamentals, artificial neural networks, convolutional networks for medical images, classic algorithms, fuzzy systems, evolutionary computing and the hybrid neuro-fuzzy system ANFIS. Every concept follows the same path. Students see the idea, implement it from scratch in NumPy [@harris2020] so that no step is hidden, and then use the standard library version in scikit-learn [@pedregosa2011] or PyTorch [@paszke2019]. All examples run on a laptop in seconds to minutes. The data either ship with scikit-learn and scikit-image [@vanderwalt2014] or are generated by the code, so no downloads or patient data are needed. The modules accompany the textbook *Computational and Biological Intelligence* [@movasagh_book], which develops the theory behind each example, but they are complete and usable without it.

# Statement of need

Biomedical engineering students increasingly need to build and judge machine-learning systems, yet most teaching materials serve them poorly. Computational-intelligence textbooks cover neural, fuzzy and evolutionary methods rigorously but rarely include runnable code or medical data. Practical Python resources focus on general machine learning and deep learning. They usually leave out fuzzy inference, evolutionary optimisation and ANFIS, and they seldom discuss clinical evaluation. Research volumes on medical deep learning assume a reader who already knows the basics.

These modules fill that gap for instructors who teach a one-semester course on computational or biological intelligence, soft computing, or machine learning for biomedical engineering. They also suit self-learners from computer science, electrical engineering, medical physics and health informatics. Prerequisites are basic calculus, linear algebra and probability. A Python refresher is included.

# Learning objectives

After completing the modules, learners should be able to:

- split medical data correctly into training, validation and test sets, and diagnose under- and overfitting from error curves;
- implement a neuron, backpropagation, a convolutional layer and pooling from scratch, and explain what a deep-learning framework automates;
- explain how radiographs and CT images are formed, using simulated phantoms, and prepare CT data with Hounsfield units and windowing;
- build, train and evaluate a CNN classifier and a small U-Net for segmentation, using Dice and IoU;
- apply and compare KNN, k-means, decision trees, SVMs and random forests on clinical data;
- design Mamdani and Sugeno fuzzy inference systems and use fuzzy c-means;
- implement a genetic algorithm, particle swarm optimisation [@kennedy1995] and differential evolution [@storn1997], and use them for feature selection and hyperparameter tuning;
- train an ANFIS [@jang1993] with hybrid least-squares and gradient learning;
- report sensitivity, specificity, ROC/AUC and balanced accuracy, and explain why accuracy alone can mislead in medicine.

# Content and instructional design

The modules follow nine units, each a notebook with its learning objectives and a sequence of numbered examples:

1. Fundamentals of machine learning, including Q-learning and a complete project from data to a saved model.
2. Neural networks, ending with a two-layer network trained on XOR in NumPy and a breast-cancer classifier.
3. Machine vision and medical imaging: hand-checked convolution and pooling, a classic cell-counting pipeline, VGG-16 parameter counts, a Beer–Lambert radiograph simulation and filtered back-projection CT.
4. Convolutional and fully convolutional networks: feature-map arithmetic, a CNN with full backpropagation in NumPy (98% test accuracy with 1,370 parameters), occlusion-sensitivity maps, and the same CNN and a small U-Net [@ronneberger2015] in PyTorch.
5. Classic algorithms on the Wisconsin breast-cancer data [@street1993].
6. Fuzzy systems [@zadeh1965; @mamdani1975], from fuzzy sets to a patient-risk inference system and a fuzzy diagnosis relation.
7. Evolutionary and hybrid systems, ending with a case study that compares grid, random and differential-evolution search for tuning an SVM under an equal evaluation budget.

Two further units cover Python for data science and evaluation metrics in medicine.

The design rests on four principles. First, *from scratch, then the library*: learners write each core algorithm in a few lines of NumPy before calling the library version, so the library is never a black box. Second, *verifiable output*: every example prints numbers that the accompanying text checks by hand, and fixed random seeds make the results reproducible. Third, *honest evaluation*: the examples keep test data for a single final use. They compare methods with equal budgets and several seeds, and they show negative results openly, such as three hyperparameter-search strategies that turn out to be tied within cross-validation noise. Fourth, *medical context with caution*: data, metrics and warnings, such as shortcut learning and patient-level splitting, come from clinical practice. No example is presented as a diagnostic tool.

Each example is short enough to run live in a lecture. A suggested classroom pattern is to change one parameter, such as the number of neighbours, the learning rate or the crossover rate, and ask students to predict the result before they run it. The repository README gives a 14-week schedule and shorter variants.

# Experience of use

The material grew out of the course *Computational and Biological Intelligence*, which the author has taught to biomedical engineering students at Islamic Azad University, Central Tehran Branch, since 2021. In the course, the examples are run and modified during lectures and serve as the starting point for assignments. All 80 scripts and nine notebooks were re-executed with Python 3.13 and current versions of the libraries before release.

# Story of the project

The examples began as lecture demonstrations written to replace slides with code that students could change and rerun. Over several years of teaching they were rewritten so that each runs on its own and prints checkable results. The medical images that the course had borrowed were replaced with simulations or openly licensed images. The collection was then organised into units that follow the chapters of the author's textbook [@movasagh_book].
